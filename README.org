#+TITLE: cctools: Claude Subscription Usage from the CLI
#+OPTIONS: toc:nil num:nil

* Overview

~cctools~ scrapes the Claude console's internal usage endpoint so that Pro/Max subscribers can read their rate-limit utilization (5-hour and 7-day windows) from the command line. Authentication is by browser session cookie.

* Design

Two composable CLIs connected by a Netscape cookie jar on disk or stdio:

- ~ccookies~ extracts cookies from a browser profile and writes a Netscape jar.
- ~ccusage~ loads a jar and fetches usage.

The jar format is the same one curl's ~-b~ / ~-c~ flags speak, so the two tools are independently usable and debuggable with standard Unix plumbing.

* Usage

#+BEGIN_SRC sh
# One-shot: extract and fetch in a single pipeline.
ccookies firefox --profile personal | ccusage --org $CLAUDE_ORG_ID

# Or cache the jar and reuse it.
ccookies firefox --profile personal -o ~/.cache/claude/cookies.txt
ccusage --cookies ~/.cache/claude/cookies.txt --org $CLAUDE_ORG_ID

# Machine-readable output for scripts and cron.
ccusage --cookies ~/.cache/claude/cookies.txt --format json \
  | jq '.five_hour.utilization'
#+END_SRC

~ccusage~ reads cookies from, in priority order: ~--cookies PATH~, ~$CLAUDE_COOKIE_JAR~, or stdin. The org ID comes from ~--org~ or ~$CLAUDE_ORG_ID~; find it in DevTools on https://claude.ai/settings/usage; it is the UUID in the request URL.

* Configuration

All inputs are CLI flags or environment variables:

| Variable            | Purpose                                 |
|---------------------+-----------------------------------------|
| ~CLAUDE_ORG_ID~     | Default ~--org~ for ~ccusage~.          |
| ~CLAUDE_COOKIE_JAR~ | Default ~--cookies~ path for ~ccusage~. |

* Limitations

The endpoint is internal and unversioned; Anthropic can rename fields or tighten the request shape without notice. Cloudflare fingerprinting means plain ~requests~ cannot reach the endpoint even with valid cookies. ~cctools~ uses ~curl_cffi~ to impersonate a real Firefox TLS handshake, and the impersonation target will need periodic bumps.

Currently only Firefox (Linux) is supported for cookie extraction.

See ~docs/endpoint.org~ for the reverse-engineered request/response reference.
